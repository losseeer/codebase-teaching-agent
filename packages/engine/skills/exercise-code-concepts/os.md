# 并发与 IO：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| 锁的获取与释放配对 | 只摘「取锁—改状态—放锁」这一段，锁本身用可控替身 | 缺陷版漏放锁时，第二次调用应卡住或状态不更新——用可判定的替身断言，不要靠真线程等待 |
| 线程池参数与溢出策略 | 摘「根据队列长度与活跃线程数决定拒绝还是入队」这段纯逻辑 | 给几组容量输入，断言返回的决策值 |
| 退避与重试次数计算 | 摘「算第 N 次该等多久」的纯函数，不摘真 sleep | 断言序列（含上限截断、抖动输入固定种子） |
| 请求上下文存取与清理 | 摘「写入—读取—清理」三步，容器用替身 | 断言清理之后读到空 |
| 延时/到期判定 | 摘「给定当前时间与任务时间，是否到期」 | 断言布尔与排序结果 |
| 批量读写分片 | 摘分片计算（每片大小、最后一片余数） | 断言分片数量与边界 |

## 常见误解转成的缺陷

- 以为原子类能保证一段逻辑整体原子 → 缺陷版把「读—改—写」拆开，测试断言并发计数结果。
- 以为 `volatile` 提供互斥 → 缺陷版去掉锁只留可见性。
- 上下文用完不清理 → 缺陷版少一次清理调用。
- 队列满时策略写反（该丢的阻塞、该阻塞的丢）→ 断言决策分支。
- 锁顺序不一致导致死锁 → 只考「两把锁的获取顺序」这一层，用替身记录顺序断言。

## 不要出成题的

真实并发度、性能差异、GC 行为、锁升级、内核调度、超时后的实际等待时间。这些在沙箱里判不出来，只能靠断言运气，学习者也无法从代码里推出结论。

## 形状示例

- **好**：一个纯函数按「队列长度 + 活跃线程数 + 最大线程数」决定新任务是入队、起新线程还是拒绝；缺陷是漏了最大线程数这一层判断。断言三组输入的三个决策值。
- **坏**：让学习者「补一段加锁代码」，测试去断言多线程跑完的计数——真实线程调度不可判定，同一份答案可能过可能挂。
