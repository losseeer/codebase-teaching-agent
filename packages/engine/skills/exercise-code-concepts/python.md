# Python 语言特性：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| 可变默认参数 | 摘「带 `def f(items=[])` 或 `def f(cache={})` 的函数」 | 连续调用两次，断言第二次不含第一次的数据；缺陷版共享同一个默认对象，状态串场 |
| 闭包晚绑定 | 摘「在循环里造 lambda 或内层函数，之后再调用」 | 断言每个闭包拿到各自那一轮的值；缺陷版全部拿到最后一轮 |
| `is` 与 `==` | 摘「用 `is` 比较值」的判定 | 造两个内容相同但非同一对象的输入（如 `int("1000")` 与大整数、`list(...)`），断言相等；缺陷版 `is` 在小整数/短字符串上偶尔通过，换个输入就挂 |
| 生成器只消费一次 | 摘「把生成器传给两个下游」的函数 | 断言两处都拿到数据（正确做法转 list 或重造）；缺陷版第二处拿到空 |
| `sort()` 返回 None | 摘「链式调用排序结果」 | 断言链式调用可用；缺陷版写 `items = items.sort()`，得到 None |
| 浅拷贝只一层 | 摘「复制嵌套结构后改内层」 | 断言改副本不影响原对象（正确做法 `copy.deepcopy`）；缺陷版用 `copy.copy` 或 `[:]`，内层仍联动 |
| 除法与整除 | 摘「按份数算配额/分页」 | 用不能整除的输入断言边界；缺陷版 `/` 与 `//` 混用，或负数向下取整方向搞反 |
| `try` 的 `else` / `finally` | 摘「异常处理里写返回值」的编排方法 | 断言 `finally` 里的 return 会覆盖 `try` 的；缺陷版以为 `try` 的返回值优先 |
| 可变对象做 dict 键 / set 元素 | 摘「把 list 塞进 set 或当键」 | 断言可哈希的替代写法（转 tuple）；缺陷版直接塞 list，运行 `TypeError` |

## 常见误解转成的缺陷

- 「函数参数是按值传递，所以改不动外面」→ 可变对象改得动（引用是按值传的引用）；可考「哪里必须显式拷贝」。
- 「`dict` 遍历顺序随机」→ 3.7 起按插入顺序，但**不要**把插入顺序当稳定契约来考（跨版本语义边界模糊）；可以考「需要顺序就显式排序」。
- 「`round()` 是四舍五入」→ 是银行家舍入（`round(2.5) == 2`）；可考「金额精度该怎么处理」。
- 「字符串拼接在循环里没问题」→ 大循环下退化成 O(n²)；只判行为不判性能，可考「`join` 与 `+=` 结果一致性」。
- 「`except Exception` 兜住就安全」→ 会连 `KeyboardInterrupt` 之外的编程错误一起吞；可考「捕获范围该收窄到哪里」。
- 「列表推导里的变量会泄漏」→ 3.x 不泄漏；这类旧知识不能当考点。

## 不要出成题的

- GIL 对多线程的实际影响、多进程/协程调度、真实并发下的竞态——需要真运行时与真时钟。
- 引用计数与循环垃圾回收的时机、`__del__` 何时被调用——不确定，不能当期望值。
- 解释器版本差异（海象运算符、`match`、类型注解的运行时行为）——换版本答案会变。
- 性能/内存（大 O 的实际耗时、生成器省了多少内存）——不属行为判分。
- 元类、描述符、`__slots__` 的实现细节——属于语言实现而非业务行为。

## 写测试时的语言约定

测试文件（`tests.py`，入口就是它）逐条跑断言，**每条用 `try/except` 包住：过了 `pass += 1`，抛了 `fail += 1`**；结尾 `print(f"TESTS {pass} {fail}")`，`fail > 0` 时 `sys.exit(1)`。只用标准库；被测代码需要的仓库内符号，写成最小替身一起放进 `hidden`。注意：`pytest` 之类第三方框架**在沙箱里不可用**。
