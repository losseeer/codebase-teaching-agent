# 出机制题（练习侧）

## 适用范围

给这个仓库出题时取这份。讲题、答追问走 `teach-code-concepts`；这两份都不改判分——**分数只由沙箱运行结果决定，题面与讲评都不参与判分**。

## 第一步：这道题能不能考

三条都过才出：

1. **摘得出来**：目标函数连它的替身能独立编译运行（不依赖容器、网络、真数据库、真实时钟与线程调度）。
2. **改一笔就变结果**：存在一个具体改动，能让那组测试从挂变过（或反过来）。给不出这个改动的题是背诵题。
3. **答案能从这份代码里读出来**：学习者不需要看仓库其他部分才能理解题面。

过不了就换考点，不要硬凑——硬凑的题要么自证失败（白花一次调用），要么学习者根本做不了。

## 第二步：按主题取可考点

主题用代码证据判（标识符、结构、配置项），不用目录名猜：

| 主题 | 附属文件 | 最常出的缺陷形状 |
| --- | --- | --- |
| 并发与 IO | `os.md` | 漏释放、复合操作没保护、上下文没清理、队列溢出策略错 |
| 传输与序列化 | `cn.md` | 超时/重试缺一个、重复投递没挡、字段契约两边不一致 |
| 数据结构与算法 | `ds.md` | 边界条件、比较器不自洽、可变对象当键、淘汰顺序反了 |
| 后端工程结构 | `backend.md` | 事务边界错、缓存与写库顺序错、幂等判据缺失 |

## 第三步：题型怎么配

- **改代码题**（`patch_edit`）：最适合「一个具体缺陷」。下发件必须是带缺陷的那一份，参考解就是仓库里摘出来的原样实现——不要自己重写一份「更好的」实现当参考解，逐字摘出。
- **从零实现题**（`author_function`）：适合小而有明确输入输出的机制件（一次退避计算、一步淘汰决策、一个归一化）。签名、形状、示例给足，算法步骤不复述。
- **修改定位题**（`change_localization`）：适合「这次改动该落在哪一层」，候选项必须都在索引里。
- **影响分析题**（`impact_analysis`）：适合「改这一处会波及谁」，标准答案由依赖图算，不要凭印象列。
- **不适合出题的**：需要真网络/真库/真实耗时才能验证的性质；跨多个文件的长链路；只有运行时配置才能确定的结论。

## 第四步：测试怎么写（判分只认这一条）

- 断言只看**纯返回值与纯状态变化**。日志、线程调度顺序、真实等待时间、异常堆栈文字都不作判据。
- 依赖时钟、随机数、线程池、连接池的：把**可判定的一层**摘出来考（算出退避序列，而不是真的 sleep）。
- 每条断言要能单独失败：一组测试全过或全挂的题没有信息量。
- 至少一条断言专门盯「这个缺陷」——否则缺陷版也能过，题就是白送。
- 脚手架按引擎约定输出那行计数结论；跑不出这行会被判「脚手架坏了」而拒题，别用退出码表达成败。

## 题面红线

- 不点出缺陷所在的那一行，也不点出要改的那个判断条件。
- 不复述参考解的算法步骤；「先加锁再查再改」这种话写进题面就等于给答案。
- 不出现测试断言里的内容（期望值、断言文案）。
- 题面里每个代码事实都必须在给学习者的摘录里能找到；摘录之外的行为不要承诺。
- 标题短而具体（点出真实符号），不写「练习 1」「数据结构专项」这类泛称。

## 自证与拒题

交题前系统会跑两趟沙箱：参考解必须全过（题不是空口）、下发件必须至少挂一条（题不是白送）。任一条不成立就拒题——**被拒时不要降低标准凑过去**，换一个考点比放宽测试有效。

## 别做什么

不要为了考某个概念编造仓库里没有的代码形状；不要把「未证实」的运行时行为写成题面事实；不要在题面里给出题目想考的结论；不要因为一次拒题就重复提交同一份题面。
