# Java 语言特性：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| `equals` / `hashCode` 不成对 | 摘一个把对象当 `HashMap` 键或放进 `HashSet` 再按值查找的方法 | 造两个「字段相同、引用不同」的对象，断言查找命中；缺陷版只重写 `equals`，`hashCode` 仍用默认，必然查不到 |
| 可变对象当键 | 摘「用对象做 map 键后又改了它的字段」 | 断言改动后仍能按原值取回（正确做法是不可变键或用值快照）；缺陷版直接改字段，取出为 null |
| 边界与溢出 | 摘「按区间/容量算结果」的方法 | 用 `Integer.MAX_VALUE`、负数、0 作输入断言；缺陷版写成 `a + b > c` 这类会溢出的比较 |
| 包装类型 `==` 比较 | 摘「两个 `Integer`/`Long` 比大小」 | 断言 `1000` 与 `1000` 相等（超出 `-128..127` 缓存区间，`==` 为 false，必须 `equals`）；缺陷版用 `==` |
| `Arrays.asList` 定长 | 摘「把数组转成列表后增删」 | 断言 `add` 成功；缺陷版直接 `Arrays.asList` 返回，`add` 抛 `UnsupportedOperationException` |
| `subList` / `Arrays.copyOfRange` 是视图 | 摘「截取子列表后改原列表」 | 断言子列表与原列表不再联动（正确做法是拷贝）；缺陷版用 `subList` 视图，改原列表时子列表跟着变 |
| 字符串拼接与不可变 | 摘「循环里累加字符串或做多次替换」 | 断言结果正确 + 用 `StringBuilder` 后结果一致（性能不判，只判行为）；缺陷版在循环里 `+=` 且逻辑写错 |
| 空集合 vs null 返回 | 摘「查询类方法」 | 断言无结果时返回空集合而不是 null（调用方直接 `for` 不 NPE）；缺陷版返回 null |
| 局部变量作用域与阴影 | 摘「内层块重新声明同名变量后误用」 | 断言外层值未被内层覆盖；缺陷版把结果赋给了内层变量 |

## 常见误解转成的缺陷

- 「`String` 是对象所以 `==` 能比内容」→ 缺陷版用 `==` 比较字符串，短字符串因常量池偶尔通过，长串/拼接串必然失败。
- 「`final` 引用不可变」→ `final List` 只是引用不可变，`add` 照样能改；可考「该在哪儿做防御性拷贝」。
- 「`switch` 忘了 `break`」→ 可考 `->` 写法与旧写法的差异；缺陷版漏 `break` 导致贯穿。
- 「异常被 catch 后没重抛，事务/调用方以为成功」→ 摘「捕获后返回默认值」的编排方法，断言调用方拿到失败信号。
- 「`Collections.unmodifiableList` 与 `List.copyOf` 的区别」→ 前者是视图（原列表改它跟着变），后者是快照；可考防御性拷贝的时机。
- 「自动装箱的 null」→ `Integer` 为 null 时参与算术会 NPE；可考「空值兜底」。

## 不要出成题的

- `HashMap` 扩容顺序、树化阈值、`ConcurrentHashMap` 的分段锁细节——实现细节，不是行为。
- 内存可见性、`volatile` 与 happens-before 的真实效果、线程调度顺序——需要真并发与真时钟，沙箱里判不了也复现不了。
- 泛型擦除导致的重载冲突、注解处理器的织入——编译期行为，改了不改变运行结果。
- 类加载顺序、`ClassLoader` 双亲委派——需要多 classloader 环境。
- JVM 参数、GC 行为、启动耗时——与环境绑定，不属代码行为。

## 写测试时的语言约定

类名与文件名必须同名（`Tests.java` 里是 `public class Tests`），入口填类名不带 `.java`；用 `public static void main` 逐条 try/catch 计数，结尾 `System.out.println("TESTS " + pass + " " + fail);`，`fail > 0` 时 `System.exit(1)`。只用 JDK，不引第三方依赖；被测代码需要的仓库内符号，写成最小替身一起放进 `hidden`。
