# TypeScript / JavaScript 语言特性：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| `==` 的隐式转换 | 摘「用宽松相等做判定」的函数 | 造 `0` 与 `"0"`、`null` 与 `undefined`、`[]` 与 `""` 等能触发转换的输入，断言各自相等/不等；缺陷版写 `==`，边界输入全错 |
| 浮点累加与比较 | 摘「金额/比例累加后判等」 | 断言 `0.1 + 0.2` 能与 `0.3` 判等（正确做法是整数分或容差比较）；缺陷版直接 `===` |
| `NaN` 不等于自身 | 摘「校验数值是否合法」 | 断言 `NaN` 被识别为非法；缺陷版写 `value === NaN` 或 `value !== NaN`，两个方向都错 |
| `Array.prototype.sort` 默认字典序 | 摘「对数字数组排序」 | 用 `[10, 9, 100]` 断言升序为 `[9, 10, 100]`；缺陷版不传比较器，得到 `[10, 100, 9]` |
| `sort` / `reverse` 原地改动 | 摘「排序后继续用原数组」 | 断言原数组未变（正确做法 `[...arr].sort()`）；缺陷版原地排序，后续读到的是排过的 |
| `async` 里的 `forEach` | 摘「批量异步处理」 | 断言全部完成后才收尾（正确做法 `for...of` 或 `Promise.all`）；缺陷版用 `forEach(async ...)`，外层不等待 |
| 浅展开只一层 | 摘「展开对象后改嵌套字段」 | 断言改副本不影响原对象（正确做法结构化拷贝）；缺陷版 `{ ...obj }`，内层仍联动 |
| `for...in` 与 `for...of` | 摘「遍历集合」 | 断言遍历到的是值不是下标/键；缺陷版对数组用 `for...in`，拿到字符串下标，累加变拼接 |
| `parseInt` 缺基数 | 摘「解析数字」 | 用 `"08"`、`"0x10"` 断言结果；缺陷版不传基数，老引擎按八进制解析 |
| 可选链与空值兜底 | 摘「深路径取值」 | 断言中间层缺失时返回兜底值而不是抛错；缺陷版逐层 `.` 取值 |

## 常见误解转成的缺陷

- 「类型断言能保证运行时形状」→ `as Foo` 什么都不做；可考「该在哪儿做运行时校验」。
- 「`typeof null === "null"`」→ 实际是 `"object"`；可考「空值判定的正确写法」。
- 「`const` 声明的对象不可变」→ 只是绑定不可变，属性照样改；可考「哪里需要冻结或拷贝」。
- 「`Array.isArray` 与 `instanceof Array` 等价」→ 跨 realm 时后者会失效；可考「鸭子类型判定」。
- 「`JSON.parse` 失败返回 null」→ 会抛异常；可考「解析失败的分支」。
- 「`delete` 数组元素会缩短长度」→ 只留空洞，`length` 不变；可考「删除后长度与遍历的预期」。
- 「`Date` 相减得到天数」→ 得到毫秒；可考「单位换算」。

## 不要出成题的

- 事件循环的精确调度顺序、微任务与宏任务的交错、`await` 的具体让出时机——需要真调度环境，跨引擎（Node/Deno/浏览器）还不一致。
- 闭包与垃圾回收的回收时机、`WeakMap` 的实际清理——不确定，不能当期望值。
- 原型链、`this` 绑定的历史坑（`bind`/箭头函数的差异）——可考但容易变成背诵题，除非能落在一段真实业务代码上。
- 模块解析顺序、打包器行为、`import` 的副作用顺序——属构建期。
- 性能（大数组的 `map` vs `for`、去重的耗时）——不属行为判分。

## 写测试时的语言约定

测试文件（`tests.ts`，入口就是它）依次调用各条断言，**每条通过就 `pass += 1`、抛异常就 `fail += 1` 并把原因打到 stderr**；结尾必须打印一行 `TESTS <pass> <fail>`，`fail > 0` 时设 `process.exitCode = 1`。跨文件 `import` **必须写真实扩展名 `.ts`**（沙箱里的 node 不做 `.js`→`.ts` 的重写）。只用标准库，不引 npm 依赖；被测代码需要的仓库内符号，写成最小替身一起放进 `hidden`。
