# 后端工程结构：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| 缓存读写与失效顺序 | 摘「读—回源—写—失效」的编排函数，存储与缓存都给替身 | 用替身记录的调用顺序断言「先写库再失效」 |
| 幂等去重判定 | 摘「查过去重键后决定执行还是跳过」 | 断言首次执行、重复跳过、键缺失三种路径 |
| 状态机合法迁移 | 摘「从当前状态 + 事件算出下一状态或拒绝」 | 断言合法迁移与非法迁移被拒 |
| 事务边界的归属 | 摘「决定哪些写操作必须同成同败」的编排层，用替身记录提交/回滚 | 断言异常时回滚被调用（替身记录，不依赖真数据库） |
| 分层依赖方向 | 出修改定位题：一次「加个字段并透出到接口」该改哪几层 | 候选项都在索引里，标准答案由依赖图算 |
| 配置开关分流 | 摘「按开关值选实现」 | 断言开、关、缺省三种输入走哪条 |

## 常见误解转成的缺陷

- 同类内部方法调用绕过代理 → 注解在内部调用处不生效，可考「该把注解挪到哪个方法」这类定位题。
- 先删缓存再更新库 vs 先更新库再删缓存 → 断言调用顺序，不讨论真实并发窗口。
- 「先查一下有没有」当幂等 → 缺陷版漏了唯一键约束这一层，可考判定逻辑本身。
- 异常被吞掉导致不回滚 → 断言替身记录到回滚调用。
- 限流阈值配错层（网关 vs 应用内）→ 出定位题：这条规则该加在哪个文件。

## 不要出成题的

容器实际织入的代理形态、事务隔离级别的真实效果、配置中心运行时下发的值、分布式锁的租约续期是否真的发生、缓存击穿时的并发请求数。这些要么需要真运行时，要么需要多进程，沙箱判不了。

## 形状示例

- **好**：一个编排函数「读缓存 → 未命中回源 → 写缓存 → 返回」，缺陷是更新数据时只写库没失效缓存；替身记录两次调用，断言更新路径上失效被调用一次。
- **坏**：让学习者「把方法加上事务注解」，然后断言数据回滚——没有真数据库与真代理，加不加注解在沙箱里行为完全一样。
