# 传输与序列化：可考的点

## 能摘出来考的（含替身怎么给）

| 考点 | 摘法 | 测试怎么断 |
| --- | --- | --- |
| 超时与重试参数装配 | 摘「把配置拼成一次请求设置」的纯逻辑 | 断言最终生效的超时值与重试次数（含未配置时的默认） |
| 重试是否幂等 | 摘「这次请求能不能重试」的判定（方法、错误类型、是否已提交） | 断言几组场景的布尔结果 |
| 去重与幂等键 | 摘「从消息算出唯一键」这一段 | 断言两条重复消息算出同一个键、不同业务算出不同键 |
| 消息路由与重试队列选择 | 摘「按失败次数决定去哪条队列」 | 断言次数边界（第 N 次进重试、第 N+1 次进死信） |
| 序列化字段映射 | 摘 DTO ↔ 内部对象的转换函数 | 断言字段值与默认值、未知字段的处理 |
| 分页与批量拉取的边界 | 摘「算下一页的游标/偏移」 | 断言末页、空页、超限三种输入 |

## 常见误解转成的缺陷

- 只设了连接超时没设读超时 → 缺陷版少设一项，断言装配结果。
- 重试次数把总耗时乘起来却没封顶 → 断言总次数或总预算。
- 「发了 MQ 就等于消费成功」→ 缺陷版在发送后立即确认，测试断言确认时机（用替身记录调用顺序）。
- 缓存与库两边字段命名不一致 → 断言转换结果丢字段。
- 分页最后一片算错偏移 → 断言边界页码。

## 不要出成题的

真实网络延迟、丢包、TLS 协商、服务端超时行为、连接池实际等待时间、消息中间件的真实投递语义。沙箱里没有网络，凡是要真发一次才能验证的性质都不能考。

## 形状示例

- **好**：一个纯函数按「HTTP 方法 + 错误类型 + 是否已提交」决定要不要重试，缺陷是漏判「已提交」这一支；测试用三组输入断言布尔结果。
- **坏**：让学习者改客户端代码，然后断言「请求变快了」或「超时后 3 秒内返回」——没有真实网络与真实时钟，判不了。
