# 出厂预置技能

引擎开机时把这个目录里的技能**复制**到 `TUTOR_SKILLS_DIR` 的第一处（没配就是 `~/.codebase-tutor/skills`）。
加载器只认用户目录那一套路径，所以「出厂」和「你自己装的」在运行时没有区别：`GET /api/external` 报的出处就是真实出处。

两条规矩（写在 `src/integrations/skills.ts` 的 `installBundledSkills`）：

- **同名不覆盖**：装过一次之后你改过的那份就是你的，升级不冲掉。要拿新的，删掉那份目录再重启。
- **坏形状不搬**：`name` 必须等于目录名、小写字母/数字/单个连字符、≤64 字，`description` ≤1024 字。不合规格的原地跳过并写进开机读数，不搬进你家目录留一条永久噪音。

写一份技能 = 建一个目录 + 一份 `SKILL.md`：

```
skills/tutor-cost-audit/SKILL.md
---
name: tutor-cost-audit
description: 对账一次对话花了多少钱、哪些源码出过门：先看哪条账、两条线怎么对上。
---

正文（步骤、判据、反例）——`read_skill` 按需取，最多 12 000 字，超出会截并留声明。
同目录里的附属文件由 `read_skill(name, file)` 取，只接目录内相对路径。
```

清单（名字 + 描述）每轮都进上下文，正文只在被取时才付费。实测 6 份清单 766 字 ⇒ 每轮多付这个量级，
所以**这里只放做法，不放解释性长文**；一份技能解决一件事，能搬出系统提示词的优先。

## 现在出厂带六份（可视化四份 + 机制两份）

| 技能 | 干什么 |
| --- | --- |
| `project-visualization` | 总流程：定图类型与范围 → 先看产物在册情况 → 按证据需求查 → 读源码补语义 → `set_diagram` 一次写完整张图 |
| `diagram-architecture` | 架构图：节点是模块不是文件，边是依赖方向 |
| `diagram-flow` | 流程图：分叉必须来自控制流图的真节点 |
| `diagram-sequence` | 时序图：静态证据只给方向不给顺序，异步一律标未证实 |
| `teach-code-concepts` | 讲机制：先用代码证据判主题（OS / 网络 / 数据结构 / 后端），再取 `os.md`｜`cn.md`｜`ds.md`｜`backend.md` 那一份，按六步讲 | 
| `exercise-code-concepts` | 出机制题：考点要「改一笔就能改变测试结果」，题型映射与替身注意在正文，主题细节同样按四份附属文件取 |

两份说明书要一起读：**这几份一装，装载目录就不再是空的**，于是 `read_skill` 这个工具与那份清单会进每一次宏观设计、问答和出题回合（此前出厂目录只有本 README，等于技能默认关）。六份清单合计 766 字，每轮多付这个量级——这是「绘图按技能走」这条路线想要的效果，不是顺带发生的。技能的**权限**不看正文：能不能改图仍由作用域决定（只有宏观设计有 `set_diagram`）。

⚠️ 这里放的必须是**我们自己写的**做法。被学习仓自带的 `skills/` 永远不扫——那是提示注入面。
