# 并发、内存与 IO（讲法补充）

## 这段代码在工程里通常长什么样

- 线程池：核心数/最大数/队列容量/拒绝策略四件套，常在配置类或启动类里；`submit` 与 `execute` 混用。
- 锁：显式 `Lock` + `try/finally` 释放、`synchronized` 方法或代码块、原子类做计数、`volatile` 做可见性。
- 线程上下文：`ThreadLocal` 存请求级状态（用户、租户、链路 id），配一个拦截器/过滤器负责清理。
- 延时与重试：延时队列 + 单线程消费、定时扫描任务、时间轮。
- IO：连接池（数据库/Redis/HTTP）、NIO selector、内存映射文件、批量读写。

## 必须讲清的三件事

1. **边界在哪里**：锁保护的是哪几行、哪段代码在池外跑、上下文在哪个拦截器里被清掉。学习者最常错的是「以为整个方法都受保护」。
2. **容量与溢出策略**：队列满了之后发生什么（丢弃、调用者执行、抛异常、阻塞），这个策略是谁定的。
3. **失败的表现形式**：泄漏（线程池不关、`ThreadLocal` 不清）、死锁（两把锁顺序不一致）、饥饿（拒绝策略把任务推回调用线程）。

## 常见误解（挑与这段代码直接相关的一条讲）

- 线程池的参数「设大一点总没错」——大池把上下文切换与内存开销换成更隐蔽的雪崩。
- `ThreadLocal` 用完不清在线程池里等于把上一个请求的数据交给下一个请求。
- 原子类只保证单个操作，不保证「读—改—写」这一段逻辑整体原子。
- 有 `volatile` 就等于有锁的互斥语义。
- 延时队列的精度取决于消费者线程是否被占用，不取决于队列本身。
- 「加了锁就线程安全」——复合操作与迭代过程仍在锁外。

## 追问示例

- 「这个线程池的拒绝策略是谁设的？找不到就去看它的构造函数用的是哪个默认值。」
- 「`ThreadLocal` 的 `remove()` 在哪一行？没有的话，说明它在什么场景下会串数据。」
- 「锁住的这段里有没有网络调用或数据库查询？把那几行的耗时算进临界区会怎样？」

## 别讲什么

真实并发度、GC 行为、内核调度、锁升级细节、连接池的实际等待时间——这些都不在静态证据里。要说影响，就说「这段代码把耗时放进了临界区」这种能从行号直接看出来的判断。
