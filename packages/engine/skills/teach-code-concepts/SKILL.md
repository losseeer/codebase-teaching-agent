# 讲机制（代码问答侧）

适用于代码问答中询问「这段为什么这么写 / 这里在做什么 / 换一种是否可行」且答案落在机制层。纯业务流程讲解不在范围内；画图交由 `project-visualization`，出题交由 `exercise-code-concepts`。

## 〇、先判是否进入六步讲解

以下三条同时满足，方进入六步：

1. 问题指向具体代码或本仓库行为；
2. 答案落在机制层（为什么这么写、拦截什么、换一种是否可行）；
3. 用户未要求简短，也未表示只需概念。

任一条不满足，采用「概念速答」：不判主题、不读附属文件、不套用六步。

**概念速答**：一句话定义（使用日常语言）；一个最小例子或必要边界，说明清楚即可；标注「这是通用概念，本仓库是否如此实现需看具体代码」；不陈述本仓库参数、不指行号；末尾询问「需要结合仓库代码按机制展开吗？」

**禁止事项**：不因出现「锁 / 缓存 / 事务」等词便自动判主题、加载附属文件；不将通用定义表述为本仓库结论；不为套用六步而编造「移除后会怎样」的场景；用户要求「简单说」时，不输出六步长文。

## 一、判主题，只认代码证据

模块名、目录名、注释用词不构成证据；按命中的标识符与结构判定，命中哪个主题，即只讲该主题：

| 主题 | 附属文件 | 命中证据（示例，非穷举） |
| --- | --- | --- |
| 并发、内存、进程与 IO | `os.md` | 线程池构造与拒绝策略、`Lock`/`synchronized`/原子类、`ThreadLocal`、延时队列、信号量、selector/epoll、mmap |
| 传输、协议与序列化 | `cn.md` | socket 与 HTTP 客户端/服务端、连接池参数、超时与重试、TLS 握手、MQ 生产与消费、网关路由、序列化框架 |
| 数据结构与算法 | `ds.md` | 自写容器、比较器、堆/优先队列、LRU/LFU、Trie、跳表、并查集、环形缓冲、二分与归并 |
| 后端工程结构 | `backend.md` | 依赖注入与代理切面、事务边界、缓存读写与失效、幂等与去重、限流熔断、分层与依赖方向、埋点 |

1. **一轮只讲一个主题**。同时命中两个（如「带锁的 LRU 缓存」）时，先讲用户所问符号所在的机制，末尾用一句话说明另一层，并询问是否继续。
2. **无法判定时不归类**。四个主题均不匹配时按业务代码讲：数据流向与状态变更；不编造「这是典型的 XX 模式」。
3. 主题仅决定讲解侧重点与常见误解；具体结论仍必须来自本仓库源码行或静态产物。

## 二、按六步讲

1. **解决什么问题**：用一句不带术语的话陈述这段代码拦截的问题（「同一笔订单可能被回调两次，这里防止重复处理」）。陈述问题，不背诵定义。
2. **定位到具体行**：给出 `文件:行号`，说明谁调用它、它拦截什么。行号只能来自已读内容或静态产物。
3. **移除后的后果**：失败模式具体到「什么场景下、以什么形式出错」；无法给出具体场景时不写此条。使用「当……时走到」句式，不使用「系统会……」。
4. **本仓库的真实参数与边界**：仅陈述本仓库看到的容量、超时、重试次数、批量大小、默认值，并注明所在配置文件；配置可能被环境变量覆盖，如见到则说明。
5. **一个常见误解**：从主题附属文件里选取与这段代码直接相关的一条，不泛泛而谈。
6. **一个可自查的追问**：要求学习者从代码中查找证据（「看看这个线程池的拒绝策略是谁设的，找不到就说明用的是默认」）。

## 三、证据取用顺序

1. 有静态产物时先 `query_facts`：类型关系与注册、配置索引能直接给出接口背后的实现与字段类型。
2. `search_code` 确认仓库内是否还有其他实现，避免仅读单个文件即断言全局。
3. `read_file` 阅读关键片段：参数、条件、异常处理都在正文里。
4. 跨文件调用关系使用上下文中的调用边与邻接信息，不做推断。

## 四、静态证据无法覆盖的内容

反射与动态代理的织入点、依赖注入实际选中的实现、运行时被环境变量或配置中心覆盖的参数、线程调度与真实耗时、异步回调的先后顺序，均不属于静态证据。讲到时如实说明「这里只能看到注册处，实际生效值需在配置或运行环境确认」。未读到的参数不写默认值；`read_file` 被截断、`query_facts` 回「不在册」时如实说明，不得以「通常」「一般来说」补足。
