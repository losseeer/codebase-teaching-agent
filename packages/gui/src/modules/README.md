# `modules/` — 教学模块（业务模块）与练习主题

> 两侧各有一套 chips：**教学侧模块 = 课程树「模块地图」的节点**（跟着仓库走），**练习侧 = 固定「程序理解题」+ 用户自建出题主题**。
> 教学侧只把**覆盖层**写进 localStorage（改名 / 隐藏 / 自建，按仓库分键），模块本体每次从课程树现算。

## 为什么不是「知识模块」了（2026-10-02）

原来这里是三个缺省「知识模块」：计算机网络 / 操作系统 / 语言特性，靠 `shared` 的关键词表 `MODULE_KEYWORDS` 把课程节点归类。这条路在业务仓里先天别扭：

- **学科名不是仓库的原生结构**。`Result.java` 被每条流程共用，关键词归类就把它重复十几遍（真仓 1209 个带锚点节点只对应 168 个文件）；
- **LLM 推荐反复判空**。「操作系统」对业务 controller 的候选池来说撑不起这个主题，模型按提示词输出空数组（判得对），界面于是永远只剩那份规则归类清单；
- 为救它做过一版**工程证据锚点表**（学科概念 → 标识符 / 依赖库），能把三个模块救活，但那是「在猜上再叠一层手写映射」，且需要按语言长期维护。**该层已随本次变更整体删除。**

现在模块跟着仓库走：导入什么仓，就有什么模块。业务名字（`博客与评论 REST 接口`、`缓存与可靠消息工具`）本身就是最好的检索词，不再需要翻译层猜。

## 数据从哪来

| 环节 | 实现 |
|---|---|
| 模块本体 | `courseModules(tree)`：取 `root.children` 里 id 为 `modules` 的分支（engine `coursetree/build.ts` 固定给这个 id），每个子节点 = 一个模块 |
| 模块 id | `module:<目录>`（build 时按锚点目录生成，**跨重新导入稳定**），所以覆盖层按 id 存不会因改名而漂 |
| 文件清单 | `moduleEntries(node)`：本节点锚点 + 子孙锚点，**按 path 去重、保留最浅层那条**；条目带树节点 id，点击即可回查选中（断链自动跳过） |
| 覆盖层 | `loadModuleOverrides(repositoryId)` → `{ renamed, hidden, custom }`，三个键分别落 `codebase-tutor.renamed-modules.<repo>` / `.hidden-modules.<repo>` / `.modules.<repo>` |
| 推荐顺序 | 仍走 `GET /module-entries`（LLM 从该模块的候选里挑最多 5 个并给理由）；LLM 不可用/判空/失败时**直接列模块自己的文件清单**，引擎用 `reason` 说明是哪一种 |
| 选中项 | `codebase-tutor.module.teaching.<repo>`；模块被隐藏或树里没了才回落 |

练习侧不变：`codebase-tutor.practice-modules` 只存自建主题，「程序理解题」是固定项（`COMPREHENSION_MODULE_ID`，出题分派的判据）。

## 面板行为（`ModulesPane.tsx`）

- 模块可能几十个（真仓 30 个）。**教学侧是三个下拉**：`主干 / 设施 / 外围`（有自建模块时再加「自建」），整块三行 + 一颗 `配置`；**练习侧仍是 chips 平铺**（主题是少量自建项）。
- **分级折叠 / 下拉的判据**：引擎在 `GET /course` 响应前给每个模块节点现算 `tier`（`annotateModuleTiers`，判据 = 该模块**可见文件**的 `FileRole`：**含执行入口、或主干文件占到可见文件的 1/4** → 主干；否则有 `support`/`infra` → 设施；只剩 `tool`/`test` → 外围。2026-10-06 实测 dianping 10 / 9 / 11，Xingyan 8 / 6 / 12）。三条实现约束：
  - 占比这一档是补的：旧判据「有一个主干文件就算主干」在 Xingyan 让一个 66 个可见文件的模块全靠 1 个文件撑成主干，三档比例就读不出模块大小了；
  - 清单里一个 tier 都没有（练习侧主题、旧引擎响应）→ **退回 chips 平铺**，不凭空造分级标题；
  - 触发器上**直接写当前选中模块名 + 该区数量**（折起来也不会让人以为模块变少了），面板内按文件数降序；`↑↓ Enter Esc` 可键盘选；
  - 开合状态由父组件持 `openKey`——**同时只开一个面板**，`配置` 展开时下拉自动收起。
- **判据外露 + 手动改档**（2026-10-06，接开发日志 §35.4）：`tierEvidence` 随 `tier` 一起现算（可见文件数、主干数、占比、定档文件、一句话原因），悬停与「配置」面板都显示——分不准的前提是先看得见为什么这么分。「配置」里每个模块给三个档位按钮，点下去只改这个界面的分组，**并落一条 `module_tier_overridden` 到审计线**（payload 带引擎当时算的占比）：结构判据没有真值可比，这些改档记录就是将来判「判据改对了没」的唯一依据。改档存在本地覆盖层（与改名/隐藏同键规则），点「恢复全部模块」一起清掉。
- **没有模块筛选框**（2026-10-04 用户要求取消；上一版「筛选 N 个模块」输入框与「外围默认折起的 chips」都被这版下拉取代）。
- 下拉本身是共用件 `../ui/OptionDropdown.tsx`（流程视图的「核心流程入口」也用它）：开合状态**留在调用方**，因为这里要「三个区同时只开一个」，而流程视图只有一个下拉——组件内部管 state 就协调不了。样式走 `.picker*` 共用类，分级色点用 `tone-core / tone-facility / tone-periphery / tone-custom` 修饰符。
- tier 只在响应时算、**不写进课程树**：角色是纯函数（几毫秒），已导入的仓库不用重烧就能看到分级，且角色口径变动不会连带课程树缓存失效。
- chip / 下拉项都带**文件数**，悬停显示模块职责摘要 + 这一档的分级依据（`hoverText`，见上）。
- `treeDerived` 决定文案：教学侧的「删除」实际是**隐藏**（确认框与 toast 都写「隐藏」，并说明点「恢复全部模块」或重新导入会回来）；练习侧的自建主题删除是真删除。
- 「恢复全部模块」= 清空覆盖层（撤销改名、恢复隐藏、清掉自建、**恢复引擎判据的档位**），有确认框。

## 模块列表怎么保持可读（2026-10-02 精炼）

真仓实测 35 个模块里有 **20 个只有 1 个文件**——「模块 = 一个目录」会把功能区切成同名碎片（三个 chip 都叫 `Grafana 大盘…`）。engine 侧两条规则管住它：

- **碎片合并**（`coursetree/build.ts` 的 `groupModuleFiles`）：文件数 < 2 的目录按顶层功能区归堆，同区 ≥2 个碎片才合成一个模块。两条护栏：`src`/`lib`/`app`/`packages`/`cmd`/`internal` 这些**源码根下面永不合并**（`entity`/`repository` 是有语义的包边界，合成大杂烩更糟）；**落单的小目录保持原路径**成模块，不硬挂到空泛的区域名下。真仓效果 35 → 30。
- **标题写给学习者**（`coursetree/llm-refine.ts`）：提示词要求「刚拿到这个仓库、不懂其业务的学习者也看得懂」，禁止只写产品名/工具名/目录名；标题上限 18 → 24，且按边界收长（标识符永不切断，散文加省略号）。产出对比：`Grafana 大盘 provisi` → `监控看板：秒杀与订单指标`。

⚠️ **生效条件**：两者都改在**建树/润色**阶段，只对下一次分析生效。已导入的仓库存着旧课程树（引擎没有「只重跑润色」的接口），要看到新列表得重新导入。`REFINEMENT_CONTRACT_VERSION` 已 bump 到 `refine-v3`，旧标记的仓库在下次分析时会重润一次。

## 历史与不可比区间

journal 里 2026-10-02 之前的 `entry_adopted` / `entry_overridden` / `module_switched` 事件，`module` 字段是 `network` / `os` / `lang`，`source` 字段是 `heuristic`；之后是 `module:<目录>` 与 `module_files`。**不迁移历史数据**，模块维度的统计跨这个日期不可比。细节见 `docs/开发关键点问题与解决方案.md` 第二十节。
